# NovelSeek Ultra PC 2.1.1 更新说明

2.1.1 同步 Android 1.6.2 的 ComfyUI 外网连接和自签名证书修复。没有自有域名时，只要隧道提供的域名与证书匹配，就可以独立核对完整 SHA-256 后，在桌面端授权使用该服务器，无需安装系统证书。

本次保留桌面 2.1.0 的创作工作台、双智能体和 Android ZIP／JSON 互通。只同步 ComfyUI 修复，不包含 Android 1.6.1 的其他功能。沿用原数据目录标识 `com.novelseek.pro`，不迁移或改写现有小说。

## 设置页与连接诊断

- 增加证书查看、完整指纹显示、明确勾选批准和“撤销本机授权”。证书主题、签发者及有效期可在弹窗核对，默认不能直接批准。
- 增加独立“应用图片设置”，不受未填写的文本模型配置影响；清楚区分当前草稿测试地址与实际生成使用的已保存地址。
- 保留公网远程端口、IPv6 和反向代理路径，提供显式 HTTPS 切换；拒绝带登录凭据、查询参数和不合法端口的地址。
- 测试实际 ComfyUI API，不把 HTTP 200 登录页当作连接成功；显示 HTTPS、证书、网络、网关及重定向错误。

首次使用：填写完整 `https://隧道域名:远程端口`，应用图片设置，查看证书并与电脑端公共证书的完整 SHA-256 独立比对，勾选确认后批准，再测试连接并生成一张小图。见 [配置指南](https://github.com/QwenchC/NovelSeek-Ultra-PC/blob/v2.1.1/docs/COMFYUI_REMOTE.md)。

## 安全与授权范围

授权严格绑定本机上的 HTTPS 主机、端口和完整证书，保留主机名、有效期和握手验证。证书变化会阻断，授权不会传播到其他地址或重定向目标，不进入书库备份，也不影响文本模型及 Pollinations。

生成任务提交、进度轮询和图片下载都检查同一授权版本；撤销或替换授权会终止旧请求。撤销无法保存时，当前进程仍拒绝旧授权，并明确提示重试及重启可能恢复旧记录。证书观察本身不发送 HTTP 或授予信任。

HTTPS 保护传输，不等于访问鉴权。不要把无鉴权 ComfyUI 任意公开使用；网关交互式登录和凭据仍不支持。

## 测试与安装

118 项前端回归和 43 项原生测试通过，包含真实 Android ZIP 互操作输入。公网测试另行显式执行，通过默认拒绝、授权后成功和撤销后拒绝，并完成一张 256×256 图片的提交、轮询、下载及完整解码。具体测试步骤和校验值见 [验证记录](https://github.com/QwenchC/NovelSeek-Ultra-PC/blob/v2.1.1/docs/2.1.1-VERIFICATION.md)。

Release 提供 Windows x64 NSIS 安装包 `NovelSeek-Ultra-PC-v2.1.1-x64-setup.exe` 和 `SHA256SUMS.txt`。安装包未配置 Windows 代码签名；安装前先导出作品备份。已有正式书库的覆盖升级、原生设置界面完整交互、大图并发和后台长任务仍需人工验收。
